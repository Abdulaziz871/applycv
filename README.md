# مُقدِّم (Muqaddim)

تطبيق خاص (عربي RTL) يساعدك أنت وعائلتك على التقديم للوظائف بالإيميل: ترفع سيرتك الذاتية (Word) مرة واحدة، تلصق وصف الوظيفة، فيخصّص الذكاء الاصطناعي السيرة ويكتب رسالة تقديم قصيرة، **وتراجع كل شيء قبل أي تنزيل أو إرسال**.

> **الحالة:** المرحلتان مكتملتان: الأولى (السيرة، التخصيص، المراجعة، PDF، السجل، النسخ الاحتياطي) والثانية (الإرسال عبر Gmail بطابور واعتماد يدوي).

كل شيء مجاني: Vercel Hobby + Gemini API (الطبقة المجانية) + `localStorage` بدل قاعدة بيانات.

---

## 1) التشغيل محلياً

المتطلبات: Node.js 20 أو أحدث، ومتصفح Chrome أو Edge.

```bash
npm install
cp .env.example .env.local     # ثم عدّل القيم (الخطوة 2)
npm run dev                    # http://localhost:3000
```

### الحصول على مفتاح Gemini المجاني

1. افتح <https://aistudio.google.com/apikey> وسجّل الدخول بحساب Google.
2. اضغط **Create API key** وانسخ المفتاح.
3. ضعه في `.env.local` كقيمة `GEMINI_API_KEY`. لا حاجة لبطاقة ائتمان.

> الطبقة المجانية لها حد يومي وحد بالدقيقة. عند تجاوزه يظهر: «تم الوصول للحد اليومي المجاني، حاول لاحقاً». التطبيق يعيد المحاولة تلقائياً مرتين قبل أن يعرض الرسالة.

## 2) متغيرات البيئة

| المتغير | الوصف |
|---|---|
| `APP_PASSWORD` | كلمة السر المشتركة لدخول التطبيق |
| `SESSION_SECRET` | سر توقيع الجلسة (32 حرفاً فأكثر). ولّده بـ `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `GEMINI_API_KEY` | مفتاح Gemini |
| `GEMINI_MODEL` | اسم النموذج (الافتراضي `gemini-3.6-flash`). اختر نموذج Flash ضمن الطبقة المجانية؛ راجع <https://ai.google.dev/gemini-api/docs/models>. إن تعبت من الحد اليومي جرّب نموذج `flash-lite` (حدوده أوسع) |
| `GEMINI_FALLBACK_MODELS` | اختياري: نماذج احتياطية مفصولة بفواصل تُجرَّب تلقائياً إذا كان النموذج الأساسي مزدحماً (خطأ 503) أو انتهى حده. الافتراضي `gemini-3.7-flash,gemini-3.5-flash,gemini-3.5-flash-lite` |
| `CHROME_PATH` | **للتطوير المحلي فقط**: مسار Chrome/Edge لتصدير PDF، مثل `C:\Program Files\Google\Chrome\Application\chrome.exe`. على Vercel اتركه فارغاً |
| `AI_PROVIDER` | `mock` لتجربة التطبيق بدون مفتاح (يعمل خارج الإنتاج فقط، ذكاؤه وهمي) |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `GOOGLE_REDIRECT_URI` | لربط Gmail والإرسال (الخطوة 9) |
| `GMAIL_MODE` | `mock` لتجربة الإرسال بلا Google (خارج الإنتاج فقط) |

لا ترفع `.env.local` إلى Git أبداً (مُستثنى في `.gitignore`).

## 3) النشر على Vercel (مجاناً)

1. ارفع المشروع إلى مستودع GitHub (خاص).
2. في <https://vercel.com/new> استورد المستودع (خطة Hobby).
3. في **Settings → Environment Variables** أضف: `APP_PASSWORD`, `SESSION_SECRET`, `GEMINI_API_KEY`, `GEMINI_MODEL`، وللإرسال: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`. **لا** تضف `CHROME_PATH` ولا `AI_PROVIDER` ولا `GMAIL_MODE`.
4. اضغط **Deploy**.

ملاحظات:
- تصدير PDF يستخدم `@sparticuz/chromium` (يعمل على Vercel). الخطوط العربية والإنجليزية **مضمّنة في المستودع** (`public/fonts`) وتُدمج داخل الـ PDF لأن Chromium على Vercel لا يملك خطوطاً عربية.
- مهلة الدوال 60 ثانية (ضمن حدود Hobby).
- بدّل كلمة السر بتغيير `APP_PASSWORD` وإعادة النشر. لإنهاء كل الجلسات القائمة غيّر `SESSION_SECRET`.

## 4) طريقة الاستخدام

1. **سيرتي**: ارفع ملف `.docx` (حتى 5MB). راجع الحقول وصحّح أي خطأ ثم احفظ.
2. **وظيفة جديدة**:
   - الصق وصف الوظيفة واضغط «تخصيص السيرة»، أو اضغط «استخدام السيرة كما هي».
   - **المراجعة (إلزامية)**: ترى كل تعديل (قبل/بعد مع السبب)، ويمكنك «تراجع» عن أي تعديل، وتعديل أي حقل ورسالة التقديم، مع معاينة A4 حيّة. لا يمكن المتابعة قبل تأشير «راجعت السيرة والرسالة».
   - **الإنهاء**: «تنزيل PDF» باسم مثل `Omar_Al-Hassan_Acme.pdf`.
3. **السجل**: كل تقديم معتمد محفوظ، ويمكن إعادة تنزيل PDF منه.

### ما يفعله الذكاء الاصطناعي وما لا يفعله
- يعيد صياغة وترتيب ما هو **موجود أصلاً** في سيرتك فقط. لا يضيف مهارات ولا خبرات ولا أرقاماً.
- بجانب تعليمات النموذج، الخادم نفسه يفرض ذلك: يعيد الشركات والمسميات والتواريخ والتعليم من الأصل، يحذف أي مهارة غير موجودة أصلاً، ويرفض أي رقم جديد (ويعيد النص الأصلي مع تنبيه).
- «مطلوب وغير موجود في سيرتك» معلومة للاطلاع فقط ولا تُضاف للسيرة.
- **الخصوصية**: الإيميل ورقم الجوال لا يُرسلان للذكاء الاصطناعي؛ يُستبدلان برموز قبل الإرسال وتُعاد محلياً. لا يُسجَّل نص السيرة ولا وصف الوظيفة على الخادم.

## 5) النسخ الاحتياطي

لا توجد قاعدة بيانات: بياناتك في `localStorage` داخل هذا المتصفح وهذا الجهاز فقط. لو مسحت بيانات المتصفح أو غيّرت الجهاز فستختفي.

- **تصدير**: صفحة «النسخ الاحتياطي» ← ينزّل `muqaddim-backup-YYYY-MM-DD.json` (السيرة، السجل، سجل الإرسال، الإعدادات). لا يحتوي كلمة السر ولا الجلسة ولا أي رموز Gmail.
- **استيراد**: يتحقق من الملف بصرامة ويرفض الملفات التالفة أو الغريبة أو الأحدث من إصدار التطبيق دون تغيير أي شيء. يعرض ملخصاً (اسم السيرة، عدد التقديمات، التاريخ) ثم تختار **استبدال** (بتأكيد) أو **دمج** (بحسب المعرّف، مع الإبقاء على الأحدث).
- يظهر تنبيه هادئ إن مرّ 14 يوماً بلا نسخة احتياطية، وتلميح للاستعادة إن فُتح التطبيق ببيانات فارغة.
- لنقل بياناتك لهاتف آخر: صدّر من الأول واستورد في الثاني.

> كل شخص في العائلة يستخدم متصفحه الخاص وله بياناته الخاصة.

## 6) الاختبارات والجودة

```bash
npm run lint
npm run typecheck
npm test            # وحدات + PDF حقيقي عبر Chrome المحلي (يتخطى PDF إن لم يوجد Chrome)
npm run build
npm run fixtures    # يعيد توليد سير ذاتية تجريبية عربية/إنجليزية (.docx) في tests/fixtures
```

اختبار المتصفح الشامل (تسجيل الدخول ← رفع السيرة ← التخصيص ← المراجعة ← PDF ← نسخ احتياطي ← مسح ← استيراد):

```bash
AI_PROVIDER=mock npm run dev -- -p 3100     # نافذة أولى
npm run e2e                                 # نافذة ثانية (وللإرسال: npm run e2e:send مع GMAIL_MODE=mock)
```

هذا الاختبار يستخدم ذكاءً وهمياً، فيتحقق من سلوك التطبيق لا من جودة Gemini. لتجربة Gemini الحقيقي على السيرة التجريبية (بيانات وهمية، بدون معلومات اتصال):

```bash
GEMINI_API_KEY=... npm run smoke:ai
```

لتحويل PDF إلى صورة ومراجعة التشكيل العربي بالعين: `npx tsx scripts/pdf-to-png.ts tests/output/cv-ar.pdf`.

## 7) قيود معروفة

- **استخراج النص من PDF العربي**: النص حقيقي ومحدَّد (ليس صورة) ويظهر سليماً ومتصلاً، لكن Chromium يكتب الحروف العربية بترتيب بصري وبأشكال العرض (presentation forms)، فبعض قارئات الـ ATS قد تستخرجه معكوساً. هذا قيد في محرك الطباعة نفسه. إن طلبت شركة ملف Word فاستخدم ملفك الأصلي.
- الحد المجاني لـ Gemini يتغيّر من Google؛ قد تتغير أسماء النماذج المجانية.
- تحديد محاولات تسجيل الدخول في ذاكرة الخادم (يكفي لتطبيق عائلي؛ يُصفَّر مع إعادة تشغيل الدالة).
- المعاينة الحيّة هي نفس القالب المستخدم في PDF، لكن تقدير عدد الصفحات تقريبي.

## 8) مستقبلاً: المزامنة بين الأجهزة

إن احتجت مزامنة البيانات بين الأجهزة فيمكن إضافة **Neon Postgres** (مجاني عبر Vercel Marketplace) خلف `lib/storage.ts` دون تغيير الواجهات، لأن كل دوال التخزين غير متزامنة (async) ومتمركزة في ذلك الملف مع إصدار للبنية (`schemaVersion`) وخطاف ترحيل. **لم يُبنَ ذلك الآن.**

## 9) الإرسال بالإيميل (المرحلة الثانية)

صفحة **الإرسال بالإيميل** (`/send`):

1. **ربط Gmail** (OAuth بنطاق `gmail.send` فقط، أي إرسال بلا قراءة للبريد). يُخزَّن رمز التحديث (refresh token) في كوكي **مشفّر AES-GCM وhttpOnly** لكل متصفح؛ لا يوجد في `localStorage` ولا في ملف النسخ الاحتياطي ولا يراه JavaScript الصفحة.
2. **إضافة الجهات**: ملف CSV أو XLSX بأعمدة `email` (مطلوب) و`company` و`position` و`job_description` (اختيارية؛ تُقبل أسماء بديلة وعربية مثل «الإيميل، الشركة، الوظيفة، وصف الوظيفة»). يُقرأ الملف داخل متصفحك فقط. يُتحقق من العناوين ويُزال المكرر ويُتخطى ما سبق إرساله (من سجل الإرسال والتقديمات)، مع عرض سبب كل تخطٍّ. أو أضف بريداً واحداً يدوياً، أو من خطوة «الإنهاء» في «وظيفة جديدة» عبر «إرسال بالإيميل».
3. **تجهيز**: لكل صف فيه وصف وظيفة تُخصَّص السيرة والرسالة (نداء واحد للذكاء الاصطناعي)، وبدونه تُستخدم سيرتك كما هي مع رسالة عامة. (التجهيز متتابع بفاصل ~2.5 ثانية لتفادي حدود Gemini المجانية.)
4. **مراجعة واعتماد يدوي لكل عنصر**: نفس شاشة المراجعة (التعديلات، الرسالة، المعاينة) مع عنوان الرسالة (Subject) القابل للتعديل. لا يُرسل إلا ما اعتمدته بنفسك، وأي تعديل بعد الاعتماد يلغيه. الخادم نفسه يرفض أي طلب إرسال بلا `approved: true`.
5. **الإرسال**: من المتصفح، رسالة واحدة في كل مرة مع مرفق PDF، وبين كل رسالتين **فاصل عشوائي 20–60 ثانية**. الحد اليومي الافتراضي 30 والأقصى 100 (يُحتسب لكل يوم بتوقيت جهازك ويُفحص قبل كل رسالة). إيقاف مؤقت / متابعة / إلغاء، وحالة لكل عنصر (بانتظار / جارٍ / أُرسل / فشل مع السبب). **اترك التبويب مفتوحاً** أثناء الإرسال (يظهر تحذير قبل إغلاقه).
6. **سجل الإرسال** محفوظ في المتصفح ويدخل ضمن النسخة الاحتياطية.

لماذا الفواصل والحد؟ الإرسال الجماعي قد يجعل Gmail يصنّف الحساب «مزعجاً» أو يوقفه مؤقتاً.

قواعد أمان:
- إن انقطع الاتصال أو أُغلقت الصفحة أثناء إرسال رسالة، تُعلَّم «فشل» ولا تُعاد تلقائياً (قد تكون وصلت). تحقق من «المرسلة» في Gmail ثم اختر إعادة المحاولة.
- عند انتهاء ربط Gmail أو بلوغ حد Gmail يتوقف الطابور كله ولا تضيع أي رسالة.
- طابور الإرسال محفوظ في المتصفح لكنه **ليس** جزءاً من النسخة الاحتياطية (بياناته مؤقتة)؛ أما سجل الإرسال فهو جزء منها.

### إنشاء بيانات OAuth في Google Cloud (مرة واحدة، مجاناً)

1. افتح <https://console.cloud.google.com> وأنشئ مشروعاً جديداً.
2. **APIs & Services → Library**: ابحث عن **Gmail API** واضغط **Enable**.
3. **APIs & Services → OAuth consent screen** (أو *Google Auth Platform*):
   - User type: **External**، واملأ اسم التطبيق وبريد الدعم.
   - **Scopes**: أضف `https://www.googleapis.com/auth/gmail.send` فقط.
   - **Publishing status**: اتركه **Testing** (لا حاجة لمراجعة من Google).
   - **Test users**: أضف **بريد Gmail لكل فرد من العائلة** سيربط حسابه (حتى 100). من ليس في القائمة سيرفض Google ربطه.
4. **Credentials → Create credentials → OAuth client ID → Web application**، وفي **Authorized redirect URIs** أضف:
   - محلياً: `http://localhost:3000/api/gmail/callback`
   - على Vercel: `https://<نطاقك>.vercel.app/api/gmail/callback` (يجب أن يطابق تماماً، وأضف كل نطاق تستخدمه).
5. انسخ **Client ID** و**Client secret** إلى `.env.local` وإلى متغيرات Vercel:
   `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` (نفس الرابط المسجَّل). ثم أعد النشر.
6. في التطبيق: **الإرسال بالإيميل ← ربط Gmail**. ستظهر شاشة «Google hasn't verified this app» لأن التطبيق في وضع Testing: اختر **Advanced ← Go to (unsafe)** ثم وافق على إذن الإرسال.

> **مهم:** رموز التحديث لتطبيقات وضع **Testing** تنتهي بعد **7 أيام** (قيد من Google). سيطلب التطبيق إعادة الربط (ضغطة واحدة) عند انتهائها. الرسائل غير المرسلة تبقى في الطابور.

### اختبار آمن قبل الاستخدام الحقيقي
أرسل أول رسالة لبريدك أنت: أضف بريدك في الطابور بوظيفة تجريبية، اعتمدها وابدأ الإرسال، وتحقق من وصول المرفق وشكل الرسالة (وقراءة العربية) في «الوارد».

للاختبار الآلي بلا Google ولا Gemini: `AI_PROVIDER=mock GMAIL_MODE=mock npm run dev -- -p 3100` ثم `npm run e2e:send` (في هذا الوضع يعمل كل شيء فعلياً حتى بناء الرسالة والـ PDF، ويُتخطى فقط النداء الأخير لـ Gmail، وتقصر الفواصل إلى 1–2 ثانية؛ الوضعان معطّلان تلقائياً في الإنتاج).

## 10) التقديم التلقائي على LinkedIn (إضافة Chrome)

صفحة **LinkedIn** (`/linkedin`) + إضافة Chrome في مجلد `extension/`. في المواعيد المحددة (افتراضياً 10:00 و14:00 و17:00 بتوقيت الجهاز) تفتح الإضافة نافذة جانبية في متصفحك وبحساب LinkedIn الخاص بك، وتبحث عن وظائف **Easy Apply المنشورة خلال آخر 24 ساعة** بالمسميات والمدينة المحددة، ثم لكل وظيفة: تخصّص السيرة عبر `/api/tailor` (بنفس قواعد عدم الاختلاق) وتولّد PDF وترفعه، وتعبّئ النموذج، وتلغي «متابعة الشركة»، وترسل.

- أي سؤال لا تجيب عنه «إجابات النماذج» أو السيرة (يُسأل Gemini عبر `/api/linkedin/answer` ويعيد «غير معروف» عند الشك) ← **تُتخطّى الوظيفة** ولا يُخترع جواب.
- حد لكل تشغيل وحد يومي، وفواصل عشوائية بين التقديمات. وضع **«تجربة»** يعبّئ النموذج كاملاً ثم يلغيه.
- التقديمات الناجحة تُنقل إلى «السجل» مع السيرة والرسالة ورابط الوظيفة.
- الإضافة تستخدم رمزاً (Bearer) صالحاً 90 يوماً ومقصوراً على `/api/tailor` و`/api/pdf` و`/api/linkedin/answer`؛ لا يصلح لتسجيل الدخول ولا للإرسال بالإيميل.

**التثبيت:** `chrome://extensions` ← وضع المطوّر ← **Load unpacked** ← اختر مجلد `extension`. من أيقونة الإضافة أدخل رابط الموقع (مثل `https://<نطاقك>.vercel.app`) واضغط «حفظ ومنح الإذن»، ثم في صفحة LinkedIn بالموقع اضغط «ربط الإضافة».

**شروط العمل:** Chrome مفتوح والجهاز شغّال في المواعيد (إن فات موعد بأقل من 3 ساعات يُشغَّل عند فتح Chrome). محددات LinkedIn مكتوبة لواجهة 2026 وقد تحتاج تحديثاً إن غيّر LinkedIn صفحاته.

> **تنبيه:** شروط استخدام LinkedIn تمنع أدوات التقديم الآلي، وقد يقيّد الحساب. أبقِ الحد اليومي منخفضاً.
